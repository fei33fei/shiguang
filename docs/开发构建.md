# 开发与构建

产品版本状态和下载见 [README](../README.md)；操作说明见 [用户使用说明](../使用说明.md)。

## 目录

| 目录 | 内容 |
| --- | --- |
| `web` | Windows、Android、Mac、iOS、鸿蒙共用离线界面及整理逻辑 |
| `desktop` | Electron 文件访问、移动、回退、回收站与目录保护 |
| `android` | Android Java 原生桥接、内置媒体预览、Manifest 和打包脚本 |
| `ios` | UIKit / WKWebView / PhotoKit / AVPlayer / QuickLook 工程 |
| `harmony` | HarmonyOS NEXT 5 / API 12 ArkTS 工程 |
| `tests` | 核心逻辑、文件操作、浏览器触摸与平台桥接模拟 |
| `scripts` | 共用资源同步、iOS 工程生成、源码导出、Mac 归档与校验 |
| `platforms` | 适配限制、验证记录、Mac 签名脚本及改动前源码快照 |
| `release` | 本地交付目录；仓库只跟踪此处说明及校验文本，二进制见 Releases |

## 桌面与共用逻辑

需要 Node.js 22+。在项目根目录执行：

```bash
npm ci
npm test
npm start
npm run dist:win
```

在 macOS 上构建两种架构：

```bash
npm run dist:mac
```

当前下载的 Mac 包是由 Windows 重打包的未签名预览，未进行 Mac 启动验证。`npm run dist:mac:cross` 需先准备 `.tools/mac-cache` 中的 Electron 45.2.2 Darwin x64、arm64 ZIP 与对应 `SHASUMS256.txt`；`node scripts/verify-mac.cjs` 只验证归档结构，不能代替原生运行测试。

## Android

需要 JDK 21（配置 `JAVA_HOME`）、Android API 35 与 Build Tools 35.0.0。按脚本当前路径准备：

- `.tools/platform/android-35/android.jar`
- `.tools/build-tools/android-15/` 中的 `aapt`、`d8`、`zipalign`、`apksigner`

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File android/build.ps1
```

`android/build.ps1` 现在转到独立的 `variants/android-universal` 工程；原 0.3.3 构建脚本另存为 `android/build-legacy-033.ps1`。通用新界面不修改桌面、iOS、鸿蒙的共用资源。脚本输出 `release/Shiguang-Android-0.3.7-universal.apk`。首次构建会在 `android/signing` 生成本地密钥和随机密码；它们不在仓库中。新密钥生成的 APK 不能覆盖原发布签名安装的应用。请妥善保存自己的签名材料。

小米专属保留包是适配前原版，内部版本码 7；通用及小米 0.3.7 内部版本码 13。切换回低版本码不能保证直接覆盖安装，卸载或清数据会丢失整理索引。

## iOS 与鸿蒙

先同步共用页面：

```bash
npm run prepare:mobile
```

iOS 需要 Mac / Xcode：

```bash
bash ios/build.sh simulator
APPLE_TEAM_ID=自己的团队ID bash ios/build.sh device
```

鸿蒙需要 DevEco Studio 5+、HarmonyOS 5 SDK、自己的设备签名，以及相关媒体权限审批：

```powershell
$env:DEVECO_HOME = 'DevEco Studio 的安装目录'
powershell -ExecutionPolicy Bypass -File harmony/build.ps1
```

两者均尚未由对应 SDK 编译和真机验证。模拟器产物不能直接安装到 iPhone；未签名工程不等于可安装 HAP。平台 API 限制详见 [适配说明](../platforms/适配说明.md)。

## 验证

```bash
npm test
node tests/e2e.cjs
node tests/folders-e2e.cjs
node tests/permissions-e2e.cjs
node tests/overview-e2e.cjs
node tests/video-ui-e2e.cjs
node tests/swipe-ui-e2e.cjs
node tests/mobile-platforms-e2e.cjs
```

现有 E2E 脚本使用 Windows Chrome 路径；桌面 E2E 还使用 `.tools/electron/electron.exe`。换机器需按实际安装位置调整。测试创建 `test-results` 中的样例文件与独立数据目录，其中 Windows 回收站用例只处理自建样例。

`.github/workflows/apple-validation.yml` 提供手动触发的 Mac 打包与 iOS 模拟器编译入口。仓库上传本身不会自动运行该工作流。
