# 拾光相册 0.3.3 多平台适配

本轮以已保留的 0.3.3 为基准，保留时间顺序、左滑下一张／右滑上一张、原位跳过、上滑待删除、两次回退、5 列分类方格、双指缩略图缩放和本地视频入口。各设备独立保存整理状态，不提供账号、同步、云存储或收费功能。

**这不是“全部平台已适配完成并通过真机验收”。** 可直接试装的是 APK 和 Windows EXE；Mac 是未签名预览包；苹果、鸿蒙目前交付的是待编译验证的工程。界面模拟不能证明原生权限、解码或回收行为正确。

原版 0.3.3 APK / EXE 保留在 release，避免在未验收新平台前失去可回退的基准。`platforms/baseline-0.3.3-source.zip` 保存本轮修改前的源文件，不含签名私钥。

## 相册与删除的差异

| 功能 | Windows / Mac 普通目录 | Android | iPhone | 鸿蒙 NEXT 5 |
| --- | --- | --- | --- | --- |
| 分类 | 实际移动原文件 | MediaStore 改媒体目录 | 修改系统相册成员关系，原片不搬进任意磁盘路径 | 拾光本机分类索引，不创建系统相册目录 |
| 删除分类 | 原位或根目录“待整理” | 原位或 DCIM/Screenshots | 解除拾光记录的相册成员关系，照片回待整理；仅尝试删除软件自建的空相册 | 解除本机分类，照片回待整理，原片保留 |
| 第一次删除 | 仅待删除标记 | 同左 | 同左 | 同左 |
| 清理待删除 | 系统回收站／废纸篓 | `createTrashRequest(true)` 并核验回收标志 | PhotoKit 系统删除请求，由系统处理最近删除 | 仅调用公开 `MediaAssetChangeRequest.deleteAssets` 请求系统回收；权限不足就保留项目并报错 |
| 已清理项目恢复 | 系统回收站／废纸篓 | 保留 0.3.3 软件内系统回收列表与恢复 | 普通 PhotoKit 不提供最近删除列表／恢复接口；在 Apple 照片恢复 | 普通应用不能调用系统回收站恢复接口；在系统相册恢复 |

安卓系统媒体回收站与小米等厂商相册的私有“最近删除”展示可能不同。本轮没有宣称解决 Civi 4 Pro／HyperOS 3.0.309.0 的展示差异，也没有改成永久删除或自动切换厂商相册。

iPhone 与鸿蒙不能完全满足“所有系统均在拾光内恢复系统回收站”和“任意物理目录移动”的要求。此处按公开接口实现，界面不显示无法兑现的恢复／安卓批量授权按钮。鸿蒙如果未获媒体写权限，第二次清理会失败并保留待删除记录；没有直接删除的降级分支。

操作系统自己的 iCloud 或厂商相册同步设置可能同步原生相册变化，拾光不控制这些系统设置。iOS 图片／视频请求禁止下载云端原片；尚未下载到本机的原片需要用户自行下载后重试。

## Android 厂商适配

同一 APK 用于小米、红米、三星、OPPO、vivo、荣耀、原生 Android 等运行 Android 11+ 的设备。使用标准媒体权限、MediaStore、系统解码器和屏幕安全区，不依赖小米包名。媒体管理设置入口不可用时回到应用设置；部分照片仍可批量写入授权。此为接口兼容目标，不代表上述品牌均已实测。

直接覆盖安装，内部版本码由 7 增到 8，显示版本仍为 0.3.3。不要卸载或清除数据。保留原密钥，源代码压缩包不包含密钥。低于 Android 11 的手机不在当前支持范围。

## Mac 使用与构建

选择对应架构 ZIP，完整解压，先读包内说明。应用尚未签名和公证，附“完成本机签名.command”供 Mac 本机 ad-hoc 签名并核验；该步骤不修改系统安全设置，也不替代正式 Developer ID 签名和公证。无法启动时需保留具体错误后继续修正，不能当作已验收版本。

Mac 整理普通文件夹；`.photoslibrary` / `.photolibrary` 图库包会被排除。需要整理 Apple 照片图库原片时，先通过 Apple 照片导出到普通目录。不会解析或修改 Photos 图库的内部数据库。

在 Mac 上从源码构建：

```bash
npm ci
npm test
npm run dist:mac
```

跨 Windows 生成的预览 ZIP 使用 `node scripts/package-mac.cjs`，需先把 Electron 45.2.2 两种 Darwin 运行时 ZIP 及 SHASUMS256.txt 放在 `.tools/mac-cache`。下载来源为 Electron 镜像，校验只说明与该发布清单一致，不等同于苹果签名验证。ZIP 重打包保留 Unix 执行位及框架符号链接；运行验证和签名仍需 Mac。

## iPhone 后续构建

需要有 Xcode 的 Mac。工程无需第三方 iOS 包管理器；Node 用于复制共用界面和生成项目文件。

```bash
bash ios/build.sh simulator
# 设备归档，需要自己的开发团队与正确的 Bundle ID / 描述文件
APPLE_TEAM_ID=你的团队ID bash ios/build.sh device
```

也可打开 `ios/Shiguang.xcodeproj`，在 Signing & Capabilities 选择开发团队，用 Xcode Run 安装到自己的手机。源码中的 `local.shiguang.album` 是示例 Bundle ID，实际签名时可能需要改为自己团队可用的 ID。

模拟器 `.app` 不能安装到 iPhone；可安装 IPA 需完成设备编译、适当的证书与描述文件及导出步骤。本轮没有这些条件，不能生成假 IPA。App Store 分发还需图标、隐私与商店资料及审核，不在本轮交付中。

## 鸿蒙 NEXT 后续构建

用 DevEco Studio 5+ 打开 `harmony`，安装 HarmonyOS 5 SDK（API 12）及配套工具。在 IDE 中配置自己的签名；真机调试用自己的账号、证书与描述文件。签名材料不得提交。

项目默认通过 PhotoViewPicker 补充所选媒体。全图库读取和媒体写权限受鸿蒙的权限／ACL 规则约束；清理功能需要申请并获准对应权限，不能通过一个软件按钮跳过平台审批。

Windows 构建入口：

```powershell
$env:DEVECO_HOME = '你的 DevEco Studio 安装目录'
powershell -ExecutionPolicy Bypass -File harmony/build.ps1
```

没有 SDK 时脚本会明确失败，不输出占位 HAP。ArkTS 严格类型、ArkWeb 资源路径、相册权限与解码均须在 SDK 编译和真机环节继续核验。目前没有签名 HAP，也没有声称兼容验证完成。
